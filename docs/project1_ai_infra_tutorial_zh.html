1. 一页总览

这个项目是什么

一个学习型 multi-agent job-search reference system。输入 JD，输出公司研究、JD 结构化、fit score、简历建议、tracker update 和 interview prep。

它真正训练什么

不是“写 prompt”，而是 agent productionization：typed state、graph orchestration、checkpoint、HITL、eval、trace、tool boundary、成本控制。

当前完成度

默认路径已经可运行；生产 demo 路径提供 FastAPI/Jinja UI、Render Blueprint、Postgres run store；optional integrations 覆盖 LangGraph、MCP SDK、LLM providers、Langfuse exporter、Postgres/pgvector、Docker。

怎么读这份文档：先跑 quickstart，再看架构图，然后按“读代码路线”打开源码。不要一开始陷进所有 optional stack； 这个项目的学习价值在于看清楚“可控 agent 系统”的边界如何逐步长出来。

2. 项目定位：为什么它适合你的转型计划

这个项目很适合作为“找工作 + AI Engineer 转型”的第一个 portfolio 项目，因为你就是用户，需求真实， 而且它自然覆盖 AI infra 面试里常问的几个主题：agent 编排、工具调用、评测、可观测性、记忆、人工审批、安全边界和部署。

3. 怎么运行

默认路径不需要 API key，也不需要网络。先用下面三条命令建立信心。

python3 -m unittest discover -s tests
python3 -m jobagent.cli eval
python3 -m jobagent.cli demo --auto-approve

Human-in-the-loop 路径

python3 -m jobagent.cli demo
python3 -m jobagent.cli resume <run_id> --approve

第一条命令会停在 NEED_USER_APPROVAL，并写入 checkpoint。第二条命令读取 checkpoint，从 tracker 继续执行。

Optional integrations

python3 -m jobagent.cli integrations
python3 -m pip install -e '.[all]'

Docker + Postgres/pgvector

docker compose config
docker compose build app
docker compose run --rm app python -m jobagent.cli eval
docker compose run --rm app sh -lc "python -m pip install --no-cache-dir -e '.[all]' && python -m unittest discover -s tests"

Minimal production Web UI

uvicorn jobagent.web.app:app --reload

打开 http://localhost:8000 后，你会看到一个很轻的操作界面：粘贴 JD、启动 run、查看 fit/resume proposal、 点击 approve 继续 tracker 和 interview prep。它不是完整 SaaS UI，而是一个可以部署到 production 平台的 portfolio product surface。

Render Blueprint deploy

git push origin main
# Render Dashboard -> New -> Blueprint -> select this GitHub repo
# Render reads render.yaml and provisions:
#   jobagent-demo      Docker web service on the free web plan

默认 render.yaml 不创建 managed Postgres，因为当前 workspace 在 paid web/database plan 上需要先补 payment info。 这版先部署一个可公开访问、可操作的 free product surface；run state 使用实例内的本地 checkpoint store，应该视为 ephemeral。 如果之后要更接近 production，再添加 Render Postgres，并把 private connection string 设置为 JOBAGENT_DATABASE_URL； Web product 检测到这个环境变量后会自动切到 Postgres run store。 也可以从 README 里的 Deploy to Render 链接进入 Render Blueprint 创建流程。 当前 live product 已发布在 https://jobagent-demo.onrender.com。

Production safety baseline：公网服务已经限制 request body 和 JD 长度，对 POST /runs 做轻量 per-client rate limit， 在读取 checkpoint 前校验 run id 格式，只接受 application/x-www-form-urlencoded 表单，并返回 CSP、HSTS、frame protection、 no-sniff、referrer policy、permissions policy 等浏览器安全头。默认 workflow 不调用外部 LLM API、不执行用户代码，也不会用用户输入去 fetch 任意外部 URL。 这让它适合 portfolio/public traffic；如果要升级成真实 SaaS，还应该加 auth、edge rate limiting、queue worker、durable Postgres 和更完整的 abuse monitoring。
最新 hardening pass：参考 LangGraph/Temporal 的 durable execution 心智、OpenAI Agents SDK 的 tracing/guardrails 分层、 OWASP LLM Top 10 的 prompt injection 与 sensitive information 风险后，当前 public surface 又补了几件准 production 能力： X-Request-ID、/readyz、/ops/status、轻量 request/run/rejection counters、 secret-shaped input detection、prompt-injection payload screening，以及 UI 上的 Production controls/Guardrails 区块。
Orchestrator/productization pass：为了更贴近 AI Engineer / Forward Deployed Engineer 的岗位要求， 项目现在把 JobSearchOrchestrator 做成一等控制平面：每个 node 执行前都会记录 run/stop/ask-human 决策、理由、 confidence 和剩余预算。每个 node 也映射到 ToolRegistry 中的注册 capability，并写出 tool audit event （input summary、output summary、status、latency、cost estimate）。Run detail page 现在不仅显示结果，还显示 orchestrator decision、tool audit、per-run quality gate；/ops/evals 可以跑内置 regression suite，返回 pass rate 和 failure categories。

4. 架构：不要让一个大 prompt 控制一切

这个项目的核心原则是：orchestrator 拥有控制平面，graph engine 执行 node loop，agent node 拥有局部认知，state 是唯一共享事实源。 这也是从 toy agent 走向 production agent 的关键分界线。

主流程

JD text
  -> JobSearchOrchestrator.plan(next_node)
  -> ToolRegistry policy/audit boundary
  -> bounded agent node
  -> JsonlTracer span
  -> JobSearchState update
  -> checkpoint / HITL / next node
  -> per-run quality summary

Production product 外壳

Browser
  -> FastAPI / Jinja minimal UI
  -> orchestrated jobagent graph workflow
  -> run detail trace table
  -> /ops/evals regression smoke
  -> Postgres web_runs table when JOBAGENT_DATABASE_URL exists
  -> local checkpoint fallback when running without DB

5. State、StopReason 和 HITL

JobSearchState 是系统中枢。agent 不互相传 loose strings，而是增量写入 typed artifacts。

JobSearchState
  run_id
  raw_job_text
  normalized_jd
  company_brief
  fit_analysis
  resume_proposal
  tracker_update
  interview_pack
  orchestrator_decisions
  tool_audit
  eval_summary
  stop_reason
  pending_node
StopReason含义为什么重要
COMPLETED完整 workflow 已完成。可作为 eval trajectory 的成功终点。
NEED_USER_APPROVAL简历/投递相关动作等待人工审批。防止 agent 自动生成或提交不可信申请材料。
NEED_MORE_INPUT输入不足，比如 JD 太短。把数据质量问题显式化。
TOOL_ERROR节点或工具调用失败。给重试、fallback、trace 诊断留接口。
LOW_CONFIDENCE系统判断不适合继续。体现 agent 不应该“永远输出”。
HITL 的关键不是问一句 yes/no。真正关键是：停在可恢复状态、写 checkpoint、保留 pending node、 把用户决策写回 state，然后从明确节点恢复。

8. 测试与验证：这个项目最应该强调的部分

AI 项目容易变成 demo，但这个项目的差异化应该是 eval-first。你要能回答：“我怎么知道 agent 没有退化？”

验证层命令覆盖内容
默认单测python3 -m unittest discover -s testsworkflow、eval runner、learning integrations；optional deps 不存在时 skip。
全依赖单测JOBAGENT_DATABASE_URL=... python -m unittest discover -s testsLangGraph compile、MCP SDK server、LLM provider constructors、Postgres round-trip。
Offline evalpython3 -m jobagent.cli eval15 条样例，检查 company、skills、stop reason、fit score。
Demo smokepython3 -m jobagent.cli demo --auto-approve端到端 run、tracker write、interview pack、trace/checkpoint artifacts。
Docker smokedocker compose run --rm app python -m jobagent.cli eval容器构建、compose 网络、Postgres service readiness。
Web smokeuvicorn jobagent.web.app:app --host 127.0.0.1 --port 8000打开首页、提交 JD、查看 paused run、approve 后完成。
Static sanitypython3 -m py_compile $(find jobagent mcp_server tests -name '*.py' -print)语法和 import-time 基础检查。
最近一次完整验证结果：默认单测 14 tests OK / 4 skipped；全依赖单测 14 tests OK； eval 15/15 passed；Docker eval 15/15 passed；容器内安装 .[all] 后 optional tests 全通过。

接下来该补的 eval

  • Source-grounding eval：公司研究必须引用真实来源或 fixture source。
  • Resume quality rubric：检查 bullet 是否包含 action、scope、impact、JD keyword。
  • Human labels：保存你对 10-20 个真实 JD 的 apply/skip 标签，用来校准 fit score。
  • Cost/latency regression：真实 LLM provider 开启后，记录每次 run 的 token、成本、延迟。

10. 下一步升级路线

现在项目已经不只是文档规划，而是有可运行 skeleton 和 optional stack。下一步应该从“更像 production AI infra”推进。

Iteration目标具体任务完成标准
0. Production product shell 先有一个能公开打开的最小 UI FastAPI/Jinja form、run detail page、approve button、Render Blueprint、Postgres run store。 Render 上可访问首页和 /healthz，本地 Web smoke 通过。
1. Eval depth 让质量证明更强 加入 source-grounding fixture、resume rubric、failure table、human labels。 README/HTML 能展示 baseline pass rate 和一次改进后的 pass rate。
2. Real LangGraph path 把教学 GraphEngine 映射到真实生态 实现一个真实 StateGraph runner，支持 interrupt/checkpoint，对照现有 runner。 同一 eval suite 可以跑教学版和 LangGraph 版。
3. Cost-aware LLM mode 接入真实模型但保持成本纪律 实现 Anthropic 或 OpenAI structured output；加 token budget、prompt version trace、mock fallback。 一次真实 run 能显示 model、tokens、latency、estimated cost。
4. Research grounding 把 company research 从本地文本升级为可溯源 加入 source fetch/cache、official careers page fixture、citation fields、grounding eval。 CompanyBrief 的 claims 能追到 sources。
5. Portfolio packaging 让项目能服务面试 录 3 分钟 demo；写 15 分钟 deep dive；加 architecture tradeoff note。 你能用代码、trace、eval、失败处理回答“为什么这样设计”。

11. 成本与安全边界

能力本地是否可免费做什么时候会花钱推荐策略
默认 demo/eval/trace免费不会，标准库路径不需要 API。永远保留为 baseline。
Docker Postgres/pgvector本地免费云数据库或托管服务会收费。本地 compose 先跑通。
Render free web demo可先免费默认无 managed DB；实例重启后本地 run state 可能丢失。先用于 public portfolio demo；不要放真实个人隐私数据。
Render web + Postgres需要 billing加 managed Postgres 或 paid web plan 时通常需要 payment info。等 demo 价值明确后再升级，并设置 JOBAGENT_DATABASE_URL。
OpenAI/Anthropic需要 key按 token 计费，多 agent 容易放大成本。默认 mock；真实 provider 必须 opt-in 并记录 budget。
Langfuse可自托管Hosted plan 或自托管运维会有成本。先 JSONL，再 exporter，再 dashboard。
Notion/Sheets MCP可能免费试用workspace 权限、OAuth、API quota 可能受限。先本地 JSONL tracker，再接外部 MCP。
安全边界：不要自动申请职位，不要自动发邮件，不要登录 credentialed job site 做 scraping。 Resume proposal、tracker write、任何外部副作用都应该先经过 human approval。

12. 面试叙事

这个项目最强的讲法不是“我做了一个帮我找工作的 agent”，而是：

推荐表述： I built a staged multi-agent job-search reference system with typed graph state, HITL checkpointing, offline evals, trace artifacts, optional Postgres/pgvector memory, MCP tool boundaries, and a migration path to LangGraph, Langfuse, and real LLM providers.

你应该准备展示的 5 个点

  1. 一次 end-to-end run：JD 输入到 tracker + interview prep。
  2. 一次 HITL pause/resume：为什么 NEED_USER_APPROVAL 是产品安全边界。
  3. 一次 eval report：15/15 passed 只是起点，说明下一步如何做 grounding/rubric/human labels。
  4. 一次 trace：每个 node 的执行顺序、耗时、stop reason、artifact。
  5. 一次 tradeoff discussion：为什么 graph-first，为什么 CLI-first，为什么 MCP 放在 integration boundary，为什么 vector memory 不能替代 relational filters。
