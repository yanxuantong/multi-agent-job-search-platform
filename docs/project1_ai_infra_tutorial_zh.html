Project 1 / AI Infra Learning Path

Multi-Agent Job Search Platform 技术复盘与下一步实现路线

这份文档把原始转型计划里的 Project 1 重新拉回技术视角：当前仓库已经完成了一个可运行、零成本的教学骨架； 但它还不是完整的 LangGraph + MCP + Langfuse + pgvector + real LLM production stack。下面会明确列出覆盖范围、缺口、成本和推荐实施顺序。

1. 当前项目定位

当前仓库最适合被理解成一个 reference implementation：它把 multi-agent 产品中最重要的边界先做清楚， 用标准库 Python 保证任何机器都能跑起来。它不是为了立刻追求“看起来很炫”，而是为了让你真的摸到 AI infra 的骨架： state、graph、checkpoint、eval、trace、tool boundary、HITL。

已经适合作为简历项目的部分

能展示 multi-agent workflow、可恢复状态机、human approval gate、offline eval、trace artifact 和 MCP-shaped boundary。

还不应夸大的部分

还没有真实 LangGraph、真实 Claude/OpenAI API、Langfuse dashboard、pgvector、官方 MCP SDK、Docker deployment。

推荐目标

把它迭代成“从零成本骨架到生产栈”的学习项目，而不是一次性堆满依赖和账号。

结论：现在实施非常值得，因为它正好能把传统 infra 经验迁移到 AI infra：你不是只写 prompt， 而是在设计一个可观测、可评估、可恢复、成本可控的 agent system。

2. 原始 Project 1 规格回放

原计划中的技术信号很明确：CLI-first，不做漂亮 UI，重点是让 hiring manager 看出你理解 agent productionization。

模块 原始期待 为什么对 AI Infra 有价值
Orchestrator LangGraph graph, state, edges, checkpoint 把 agent 从“聊天脚本”升级成可恢复的状态机。
Company Research Agent 检索公司、职位、新闻和来源 练习 RAG、source grounding、fallback、工具失败处理。
Resume Tailoring Agent JD-aware resume proposal + human approval 练习结构化输出和 HITL，避免自动生成不可信申请材料。
Application Tracker Notion/Google Sheet via MCP 练习 agent-to-tool 边界、schema validation、idempotent writes。
Interview Prep Agent 根据公司和 JD 生成准备包 练习把前序 artifact 组合为下游任务输入。
Eval Harness 15-20 offline eval cases, pass rate, failures 这是 AI infra 项目最强的信号：你知道 agent 需要回归测试。

3. 当前实现覆盖矩阵

下面是“原计划 vs 当前仓库”的诚实对照。它可以直接指导下一轮 issue 或 milestone。

原要求 当前状态 文件证据 是否足够作为经验 下一步建议
LangGraph orchestration 部分覆盖 jobagent/graph/engine.py, jobagent/graph/workflow.py 足够讲清 LangGraph 心智模型，不足以声称生产 LangGraph 使用经验。 新增真实 LangGraph branch：StateGraph, interrupt, checkpointer。
Typed shared state 已覆盖 jobagent/models.py 非常适合作为系统设计讨论入口。 保留 typed artifacts；迁移 LangGraph 时不要退回 loose dict。
HITL approval + checkpoint 已覆盖 JsonCheckpointStore, CLI resume 足够展示 pause/resume 的产品和 infra 边界。 下一步对齐 LangGraph interrupt + Postgres checkpointer。
Claude/OpenAI real model calls 未覆盖 jobagent/llm/provider.py 只有 provider boundary 边界设计有价值，但还不是 LLM SDK 实战。 实现一个 opt-in adapter：需要 API key、token budget、成本 trace。
Company research retrieval 部分覆盖 jobagent/agents/company_research.py 能讲 node responsibility，不能讲真实 web/RAG grounding。 加入 source objects、local cache、fallback to web_search 或 fixture retrieval。
Memory layering 部分覆盖 jobagent/memory/story_bank.py 有 story bank 概念，但缺 semantic/episodic memory 分层。 加 Postgres + pgvector，本地 embeddings 可先用免费模型或 deterministic fake embeddings。
Langfuse observability 部分覆盖 jobagent/observability/tracer.py 写 JSONL 能讲 trace schema；不能声称 Langfuse dashboard 经验。 加可选 Langfuse exporter，记录 prompt version、tokens、latency、cost。
MCP server 部分覆盖 mcp_server/career_research_server.py MCP-shaped stub 有教学价值，但不是官方 SDK。 用 official Python/TypeScript SDK 重写，暴露 tools/resources/prompts。
Notion/Google Sheet tracker 部分覆盖 jobagent/storage/tracker.py 写 JSONL 足够练习 idempotent write；缺真实第三方 OAuth/MCP。 先保持 JSONL，之后接一个 MCP tracker adapter。
Eval harness 15-20 cases 部分覆盖 jobagent/evals/runner.py, samples/evals/*.json 当前 eval shape 对，但数量不够。 扩到 15-20，拆 single-turn extractor eval 和 trajectory eval。
Docker/deploy touchpoint 未覆盖 暂无 Dockerfile / docker-compose.yml 本地 demo 足够；部署经验还没体现。 先加 docker-compose: app + Postgres/pgvector + optional Langfuse。

4. 从传统 Infra 到 AI Infra 的迁移映射

你的优势不是“我会写 prompt”，而是“我知道一个不稳定智能系统也需要工程边界”。这张表是面试时可以反复使用的语言。

传统 Infra 经验 AI Infra 对应物 在本项目里的落点
Service boundary Agent node boundary 每个 agent 只读写 JobSearchState 的一部分。
Request context Shared graph state JD、company brief、fit analysis、resume proposal 逐步累积。
Retry/fallback/circuit breaker Tool failure handling 下一步应加入 research fallback 和 diagnostic stop。
Logs/traces/metrics Per-agent traces, token/cost/latency 当前 JSONL trace 是 Langfuse/OpenTelemetry 的前置形态。
CI regression tests Offline eval suite python3 -m jobagent.cli eval 是 agent regression gate。
State store Checkpoint + memory checkpoint 负责恢复；story bank/pgvector 负责长期偏好和经历。
API gateway / tool integration MCP server/client 未来 career-research server 暴露公司研究工具。

5. 本地运行可行性与成本

按 2026-05-27 当前官方文档核对，最稳妥的策略是：先保持当前仓库完全免费可运行，再逐步引入需要账号或可能收费的组件。

能力 本地是否可免费做 什么时候会花钱 推荐选择
当前 demo / eval / trace 免费 不会。当前只用 Python 标准库。 继续作为 baseline，保证任何人 clone 后能跑。
Postgres + pgvector 本地免费 云数据库会收费；本地 Docker 只消耗本机资源。 第二阶段引入，先用 docker-compose。
Langfuse observability 可本地自托管 Langfuse Cloud 或企业自托管能力可能收费；自托管有运维成本。 先保留 JSONL，再加 optional Langfuse exporter。
OpenAI / Anthropic API 通常需要付费 API key 按 token 计费；agent loop 容易产生多轮成本。 做 opt-in adapter，默认不开；设置每次 run 的 token/cost budget。
MCP SDK SDK 本身免费 工具背后的第三方 API 可能收费或需要 OAuth。 先实现本地 career-research MCP server，再接外部 tracker。
Notion / Google Sheets 个人账号通常可试 高级 workspace、企业 OAuth、用量或自动化可能有限制。 先用本地 JSONL tracker，等 MCP 边界稳定后再接。
Fly.io / Render / Modal deploy 可能有免费层 需要支付方式、资源持续运行、数据库、带宽或冷启动限制。 最后做 deployment touchpoint，不要一开始就烧钱。
成本纪律：真实 LLM adapter 加入前，先做 budget guard。每次 run 记录 model、input tokens、output tokens、latency、估算成本、是否命中缓存。 这样项目会更像 AI infra，而不是一个不可控的 agent demo。

推荐的低成本路径

  1. Phase A: 保持当前零成本 skeleton，扩 eval 到 15-20 个 cases。
  2. Phase B: 加 docker-compose 的 Postgres/pgvector 和本地 checkpoint/memory adapter。
  3. Phase C: 加一个真实 LLM provider，默认 mock，只有设置 API key 才启用。
  4. Phase D: 加 optional Langfuse exporter 或本地 self-host compose profile。
  5. Phase E: 用官方 MCP SDK 重写 career-research server。
  6. Phase F: 最后做 cloud deploy touchpoint 和 README architecture screenshot。

6. 下一步技术实施路线

如果目标是“积累 agent 经验 + 面向 AI infra 转型”，我建议按下面三轮做，每轮都有可展示的产物。

Iteration 目标 具体任务 完成标准
1. Eval-first hardening 把当前 skeleton 变成可信 regression harness 扩充 15-20 cases；分 extractor eval、trajectory eval；记录 failure reason；加 source-grounding fixture。 python3 -m jobagent.cli eval 输出 pass rate、case failure table、trace path。
2. Real infra adapters 让项目碰到真实 AI infra 组件 Postgres/pgvector memory；LangGraph branch；官方 MCP SDK server；JSONL to Langfuse exporter。 docker-compose 一键起本地依赖；mock 模式仍然可零成本运行。
3. Cost-aware LLM mode 引入真实模型但控制风险 OpenAI 或 Anthropic adapter；structured output schema；budget guard；prompt version tracing；small paid smoke suite。 README 能展示一次真实 run 的 tokens、cost、latency、eval result。
简历表述建议：不要写“built a full production job search agent platform”。更强也更可信的说法是： “Built a staged multi-agent job-search reference system with typed graph state, HITL checkpointing, offline evals, trace artifacts, and a migration path to LangGraph, MCP, Langfuse, and pgvector.”

7. 代码阅读路径

这部分把 docs/LEARNING_GUIDE.md 的阅读路线融合进来。你可以按这个顺序给自己做 code walkthrough。

  1. 先读 state: jobagent/models.py。重点看 JobSearchState、artifact model、StopReason。
  2. 再读 graph: jobagent/graph/workflow.py 和 jobagent/graph/engine.py。重点看 node wiring、stop condition、checkpoint save。
  3. 逐个读 agent: jobagent/agents/。不要纠结 heuristic 文本处理，重点看 agent contract：输入来自 state，输出是 typed artifact。
  4. 跑 HITL: 先 python3 -m jobagent.cli demo，再 python3 -m jobagent.cli resume <run_id> --approve。
  5. 跑 eval: python3 -m jobagent.cli eval。把它当成 agent regression test，不只是 demo script。
  6. 看 provider boundary: jobagent/llm/provider.py 和 jobagent/prompts/registry.py。真实 LLM adapter 应该接在这里。
  7. 看 observability: jobagent/observability/tracer.py。下一步 Langfuse exporter 应该保持同样的 trace fields。
  8. 看 MCP stub: mcp_server/career_research_server.py。下一步用官方 SDK 重写时，保留 tool schema 和错误语义。

本地验证命令

python3 -m unittest discover -s tests
python3 -m jobagent.cli eval
python3 -m jobagent.cli demo --auto-approve
