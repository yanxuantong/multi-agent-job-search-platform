Multi-Agent Job Search Platform 架构说明

这份文档解释项目内部怎么分层、agent 如何协作、state 如何流动，以及未来如何把教学版本替换成 LangGraph、真实 LLM SDK、Langfuse 和 MCP。

1. 架构总览

这个项目的核心思想是：不要让一个大 prompt 隐式控制所有事情，而是用一个显式 graph 管住状态流转，每个 agent node 只做一个边界清楚的任务。

2. 目录和职责

路径职责学习重点
jobagent/models.py 定义共享 state、artifact、budget、error、stop reason。 multi-agent 系统不要只传字符串，应该传 typed state。
jobagent/graph/engine.py 小型 graph runner，负责 node 调度、trace span、停止条件。 对应 LangGraph 的 nodes、edges、interrupts、checkpointing 思路。
jobagent/graph/workflow.py 把 agent nodes 注册成一个完整 workflow。 编排逻辑集中在这里，而不是散落到每个 agent。
jobagent/agents/ 每个 agent node 负责一个 bounded task。 agent 是工作节点，不是全局控制器。
jobagent/storage/checkpoint.py 保存和读取暂停时的完整 state。 HITL 的关键不是问人，而是可恢复地暂停。
jobagent/observability/tracer.py 把每个 node 的执行事件写入 JSONL。 生产版可替换为 Langfuse 或 OpenTelemetry。
jobagent/llm/provider.py 定义未来接真实 LLM 的 provider interface。 把 Anthropic/OpenAI SDK 适配集中在一层。
jobagent/prompts/registry.py 集中管理 prompt name、version、system prompt、schema。 prompt 是工程产物，需要版本化。
jobagent/evals/runner.py 离线 eval runner。 用数据证明 agent 行为没有退化。
mcp_server/career_research_server.py MCP-shaped stdio tool boundary。 展示能力如何作为外部工具暴露出去。

3. State 如何流动

JobSearchState 是整个系统的中枢。每个 node 读取 state 的一部分，写入一个新的 artifact，然后把控制权交还给 graph。

5. HITL 和 checkpoint 设计

HITL 的关键不是在命令行问一句“是否继续”，而是把系统停在一个可以恢复的状态上。这个项目里，resume_tailor 生成简历建议后会停止：

stop_reason = NEED_USER_APPROVAL
pending_node = tracker
checkpoint_path = .jobagent/checkpoints/<run_id>.json

当你执行 resume <run_id> --approve 时，系统读取 checkpoint，把 approved 改成 true，然后从 tracker 继续。

对应生产系统

在真实 LangGraph 版本里，这一层可以替换为 LangGraph checkpointer。存储可以从本地 JSON 文件变成 Postgres、Redis 或 durable workflow storage。

6. Trace 和 Eval

Trace

JsonlTracer 为每个 node 记录 step、next node、stop reason、耗时和 metadata。文件位置是 .jobagent/runs/<run_id>/trace.jsonl。

Eval

run_eval_suite 用样例数据检查公司名、required skills、stop reason 和 minimum fit score。这是 offline regression 的雏形。

真实生产版可以继续扩展：

  • 把 JSONL trace 换成 Langfuse 或 OpenTelemetry。
  • 添加 source-grounding eval，检查公司研究是否有真实来源。
  • 添加 LLM judge rubric，但保留 deterministic checks 作为底线。
  • 把 eval pass rate、latency、cost 和 stop-reason distribution 放进 dashboard。

7. Provider 和 Prompt 边界

当前项目没有真实调用 LLM，但已经留好了替换边界：

LLMRequest
  prompt_name
  prompt_version
  system
  user
  response_schema
  metadata

LLMResponse
  content
  model
  usage

MockLLMProvider 现在只返回 deterministic response。未来可以新增：

  • AnthropicProvider.generate_structured
  • OpenAIProvider.generate_structured
  • prompt cache、token usage、cost estimation、model fallback

jobagent/prompts/registry.py 负责 prompt versioning。这样你以后做 eval regression 时，能知道某次输出来自哪个 prompt 版本。

8. 迁移到真实生产栈

教学版本生产替换替换原因
GraphEngineLangGraph StateGraph获得官方 checkpoint、interrupt、可视化和生态支持。

JsonlTracerLangfuse / OpenTelemetry观察 latency、token、cost、failure distribution。
MockLLMProviderAnthropic / OpenAI SDK真实 structured output、tool calling、model fallback。
JsonlApplicationTrackerPostgres / Notion MCP / Google Sheets MCP让投递记录成为可查询、可同步的数据。
career_research_server.py官方 MCP Python SDK让 research capability 被 Claude Desktop 或其他 MCP client 调用。

9. 读代码的建议路线

  1. 先读 jobagent/models.py，理解 state 和 artifact。
  2. 再读 jobagent/graph/workflow.py，看节点如何连接。
  3. 然后读 jobagent/graph/engine.py，看 node 如何被执行和停止。
  4. 按 workflow 顺序读 jobagent/agents/。
  5. 最后读 storage/checkpoint.py、observability/tracer.py、evals/runner.py。

这份架构说明面向学习和面试 deep dive。真正生产化时，优先替换 orchestration、provider、tracing、storage，而不是先做复杂 UI。
