第 18 章：10x Scale 与 Production Readiness：什么时候可以说它准备好了

Production readiness 不是一句自信判断，而是一组关于流量、状态、恢复、安全和验证的证据。

直接做实验 课程目录

这一章先解决什么问题

JobAgent 现在可以诚实地称为 production-shaped：它有 FastAPI surface、Docker/Render 部署、typed state、HITL、checkpoint/resume、trace/audit、guardrails、ops endpoints 和 offline eval。但它还不应该被包装成 fully production-ready SaaS。

10x scale 先考验的不是 agent prompt，而是执行层：POST /runs 目前同步跑完整 workflow；默认 local checkpoint 在 Render free instance 上是 ephemeral；in-memory rate limit 不能跨进程共享；Postgres path 存在，但还缺 connection pooling、migration/versioning、idempotent approval 和 background worker。

这一章故意先不实现这些升级，而是把生产判断记录成可复述、可验证、可逐步落地的 checklist。对 portfolio 和面试来说，这种边界意识本身就是很重要的工程经历。

一次小型展览可以靠一个工作人员现场登记、现场带路、现场收票。但如果人流变成十倍，你不会先训练他说话更漂亮，而是会先加排队系统、票据数据库、入口闸机、监控面板和应急流程。Agent product 的 10x scale 也是同一个逻辑。

扩展工程手册：把这一章做成可执行练习

这章真正解决的问题

第 18 章训练的是 production judgment。JobAgent 已经是 production-shaped：有 web surface、typed state、checkpoint、trace、eval、guardrails 和部署。但它还不是 full SaaS，因为 10x traffic 会首先打到执行、状态、恢复和运维层。

Execution当前 POST /runs 同步执行 workflow。10x 后应拆成 web request + background job + status polling。
StateLocalRunStore/JSON checkpoint 适合学习和 demo；durable beta 需要 Postgres、migration、connection pooling 和 backup。
Concurrency内存 rate limit 和单进程状态不适合多实例。生产要用共享 rate limit 和 idempotency key。
Recoveryapproval、resume、tool side effect 都需要幂等设计，避免重复提交或丢失用户决策。
Evidencereadiness 需要测试、eval、restart smoke、ops endpoint、trace 和安全验证共同证明。

代码解读：每个文件负责什么

jobagent/web/app.py

当前 request lifecycle 所在地。重点读 create_run 和 approve_run：它们告诉你同步执行、审批 resume 和错误处理在哪里发生。

jobagent/web/store.py

LocalRunStore 与 PostgresRunStore 的边界。这里决定 run summary、creator session、approval 状态和持久化能力。

jobagent/storage/checkpoint.py

workflow state checkpoint。10x 升级时，它会变成数据库表、object store 或 LangGraph checkpointer 的候选迁移点。

samples/eval_suite.json

readiness 的质量证据。每次 production-ish 改动都应该证明核心 trajectory 没退化。

render.yaml

部署层证据。它说明当前公开服务如何启动，也暴露了哪些还只是 demo 边界。

工程选择 Q&A

Q: 10x 首先扩哪里？

A: 先扩执行层和状态层：background worker、durable store、idempotency、shared rate limit。不要先优化 prompt。

Q: 什么叫 production-shaped？

A: 架构形状接近生产：有边界、状态、测试、观测、安全和部署。但容量、恢复、权限、运维证据还没达到真实 SaaS。

Q: readiness checklist 应该包含什么？

A: load、restart-resume、approval race、storage failure、guardrail bypass、eval regression、trace smoke、ops endpoint 和 cost cap。

Q: 面试时怎么讲边界不显弱？

A: 说清楚当前是 public product/portfolio surface，并列出升级顺序和验证证据。诚实边界本身就是 production thinking。

行业脉搏：把本章放到 2026 AI infra 里看

行业里的 agent platform 越来越把 runtime、durable execution、identity、policy、observability 和 eval 放在一起卖，原因很简单：agent 质量问题最后常常表现为系统可靠性问题。

这一章对应的能力不是某个新框架，而是 FDE/AI infra 面试里很有价值的判断力：能区分 demo-ready、production-shaped、production-ready，并能说清下一步工程升级顺序。

读这些链接时，不要只记产品名。更重要的是把它们映射回本项目：哪些能力已经在 JobAgent 里有教学版，哪些能力属于未来的生产升级。
