扩展工程手册：把这一章做成可执行练习

这章真正解决的问题

第 21 章把前面所有能力串成一次真实工程交付：新增一个 bounded agent，并把它接入 typed state、workflow、checkpoint、eval、trace、web UI 和 portfolio narrative。它考的是闭环，不是单点功能。

Artifact先在 models.py 定义 typed output，例如 SalaryAnalysis 或 NetworkingStrategy。
Agent在 jobagent/agents/ 新增 bounded node，只读它需要的 state，只写它负责的 artifact。
Graph在 workflow.py 接入 node 和 edge，决定它在 JD、company、fit、resume、approval 之间的位置。
Eval在 samples/eval_suite.json 和 runner/tests 里覆盖 trajectory 与关键输出。
Product在 run.html 展示新 artifact，让用户看到它为什么有用。
Story最后写 README/portfolio 叙事：你如何设计 bounded multi-agent workflow，并如何验证它。

代码解读：每个文件负责什么

jobagent/models.py

新增能力的 contract 起点。不要先写自由 dict，先定义 dataclass/schema，后续 checkpoint、UI、eval 都会受益。

jobagent/agents/

bounded agent 的实现目录。一个新 agent 应该职责窄、输入明确、输出结构化、失败模式可解释。

jobagent/graph/workflow.py

调度接入点。新增 node 后必须决定边的位置、HITL 前后关系、resume 行为和 stop_reason。

jobagent/evals/runner.py

如果新 artifact 是核心能力，eval runner 需要能检查它。否则功能只是 UI 上看起来存在，缺少回归证据。

jobagent/web/templates/run.html

产品展示层。用户应该能看懂新 agent 产物、证据和下一步动作，而不是只看到 JSON。

tests/

小粒度行为保护。新增 agent 通常需要 agent unit test、workflow trajectory test、web render/API test。

动手实验：按顺序执行

实验 1：选择一个新 agent 并定位插入点

rg -n "graph.add_node|graph.add_edge|resume_tailor|fit_analysis|interview_prep" jobagent/graph jobagent/agents

目标：判断新 agent 应该依赖哪些上游 artifact，以及它是否应该在 HITL 前出现。

实验 2：列出需要触碰的 contract

目标：把新增功能拆成 state、serialization、workflow、eval、UI、tests 六块，不要只改 agent 函数。

实验 3：定义完成标准

.venv/bin/python -m unittest discover -s tests
.venv/bin/python -m jobagent.cli eval
.venv/bin/python -m jobagent.cli retrieval-eval

目标：把 capstone 的完成标准写成能跑的命令。真正的项目经历要能被验证。

工程选择 Q&A

Q: 第一个 capstone agent 选什么最好？

A: 选能服务 AI engineer/FDE 求职叙事的能力：company risk analysis、networking strategy、salary/leveling analysis、interview loop planner。它要能展示产品价值和 infra 边界。

Q: 新 agent 需要 HITL 吗？

A: 如果它影响真实申请、外部写入、联系人触达或简历最终内容，就需要 HITL 或至少 review gate。如果只是内部分析，可先不需要。

Q: 需要真实 LLM 才算完整吗？

A: 不需要。先 deterministic baseline + provider boundary + eval。真实 LLM 是质量升级，不是系统设计的前提。

Q: Portfolio 叙事怎么写？

A: 写你如何划分 bounded agent、如何管理 shared state、如何做 HITL、RAG、trace、eval、deployment 和安全边界。重点是工程判断，不是炫功能数量。
