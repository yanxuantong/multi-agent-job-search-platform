第 17 章：Deployment：从本地 demo 到公开 portfolio

部署 agent product，不只是把 API 跑起来，还要说明状态、成本和安全边界。

直接做实验 课程目录

这一章先解决什么问题

本项目提供 Dockerfile、docker-compose、Render Blueprint、health/readiness/ops endpoints。

Hosted demo 默认不用 managed Postgres，因此 run state 在 free web instance 内可能 ephemeral。这不是失败，而是清楚标注 demo 边界。

更接近 production 的路径是：durable Postgres state、queue-backed worker、auth、edge rate limit、budget tracking、observability backend。

临时展台可以用折叠桌，但你要告诉观众它不是永久门店。Portfolio deployment 也一样：能用、好看、边界诚实，比假装 enterprise SaaS 更可信。

这章真正解决的问题

第 17 章回答“它能不能被别人打开使用”。部署 agent product 不是只把 Python 服务跑起来，还要说明健康检查、配置、状态持久性、成本、安全边界和后续升级路径。

ContainerDockerfile 定义可重复运行环境，生产命令启动 uvicorn jobagent.web.app:app。
Local Stackdocker-compose.yml 让 web、Postgres、Langfuse 等组件可以在本地组合验证。
Render Blueprintrender.yaml 描述托管服务、健康检查、环境变量和 public demo mode。
Runtime Health/healthz 证明进程活着；/readyz 应该证明依赖和 store 能工作。
Boundary公开 demo 可以使用轻量 state，但 production SaaS 需要 durable store、auth、queue、observability backend 和 budget controls。

工程选择 Q&A

Q: Render 部署就等于 production-ready 吗？

A: 不等于。它证明可公开访问和可运行，但 production-ready 还需要持久状态、认证、队列、审计、监控、预算和恢复证据。

Q: 什么时候必须上 Postgres？

A: 当用户期望历史 run 不丢、审批可恢复、多实例共享状态，或者你要分析运行数据时。

Q: 什么时候必须上 queue？

A: 当 workflow 超过 request timeout、外部 API 慢、需要 retry/backoff，或并发 run 会阻塞 web worker 时。

Q: 免费托管会不会有成本风险？

A: 如果不接真实 LLM，成本主要是 hosting。接真实模型后必须做 rate limit、budget cap、key isolation 和 abuse monitoring。
