第 12 章：LangGraph：从教学 GraphEngine 迁移到工业框架

先理解本地 graph，再判断是否需要 LangGraph 的生产能力。

直接做实验 课程目录

这一章先解决什么问题

GraphEngine 是为了把概念讲清楚；langgraph_reference.py 是迁移 mental model。

LangGraph 的价值在 durable execution、interrupt、checkpointer、conditional routing、streaming、deployment、debug visibility。

迁移不是为了追框架，而是当本地 engine 的复杂度开始复制这些能力时，选择成熟实现。

教学时可以用纸飞机解释空气动力学；真正载客时要用经过认证的飞机。GraphEngine 是纸飞机，LangGraph 是可运营飞机，但你得先懂飞行原理。

扩展工程手册：把这一章做成可执行练习

这章真正解决的问题

第 12 章不是要你立刻把教学版 GraphEngine 替换掉，而是要建立迁移判断力：当 workflow 开始需要 durable execution、interrupt、resume、streaming、distributed worker 和可视化调试时，哪些本地概念应该一一映射到 LangGraph。

Teaching Enginejobagent/graph/engine.py 用最少代码表达 node、edge、budget、stop_reason、pending_node、trace span。它是理解概念的底座。
Workflow Contractjobagent/graph/workflow.py 是 canonical graph wiring。迁移到 LangGraph 时，最应该保持的是节点职责和状态 contract，而不是一行行照搬 engine。
Reference Adapterjobagent/graph/langgraph_reference.py 展示如何把 JobSearchState 包进 StateGraph，并把 resume gate 映射成 conditional routing。
Interrupt Boundary当前系统用 StopReason.NEED_USER_APPROVAL 和 pending_node 表达 HITL 暂停；LangGraph 里可以升级为 interrupt/checkpointer 模式。
DurabilityJsonCheckpointStore 是学习版 checkpoint；生产路径会迁移到 LangGraph checkpointer 或数据库-backed state。

代码解读：每个文件负责什么

jobagent/graph/engine.py

本地 orchestrator。它负责按节点名调度、检查预算、记录 trace、处理 stop_reason，并在暂停时写下 pending_node。读这个文件时重点看控制流，而不是把它当成生产框架。

jobagent/graph/workflow.py

业务 workflow 的唯一装配点。哪些 agent 节点存在、它们如何连接、resume 后从哪里继续，都应该先在这里理解清楚。

jobagent/graph/langgraph_reference.py

LangGraph 迁移参考，不是默认 runtime。它把教学 engine 的概念翻译成 StateGraph、conditional edges 和 checkpointer，并用 optional dependency 保持主路径轻量。

jobagent/models.py

JobSearchState 是迁移时最重要的资产。框架可以换，但 state schema、artifact 字段、stop_reason 和审批语义必须稳定。

tests/test_optional_integrations.py

验证 optional integration 的边界：没装 LangGraph 时不让主测试坏掉；装了以后能检查 reference app 构建路径。

动手实验：按顺序执行

实验 1：对照两个 graph 文件

目标：找出本地 engine 与 LangGraph reference 的概念映射。

sed -n '1,140p' jobagent/graph/engine.py
sed -n '1,220p' jobagent/graph/langgraph_reference.py

记录：node wrapper 在哪里、conditional route 在哪里、checkpoint 在哪里、HITL 暂停如何表达。

实验 2：跑 optional integration 测试

目标：确认 LangGraph 是可选增强，不影响默认学习路径。

.venv/bin/python -m unittest tests.test_optional_integrations

如果环境没装 LangGraph，测试应该 skip 或验证 graceful boundary；这就是 optional dependency 的正确行为。

实验 3：写一张迁移表

目标：把“换框架”变成可执行迁移计划。

rg -n "GraphEngine|pending_node|StopReason|JsonCheckpointStore|build_langgraph" jobagent tests

把每个结果分到四列：current concept、LangGraph concept、must preserve、migration risk。这个表比直接改代码更有价值。

工程选择 Q&A

Q: 现在应该直接迁移 LangGraph 吗？

A: 不急。当前目标是学习和 portfolio，教学 engine 更透明。等你要做长任务、复杂分支、跨进程 resume、生产级 checkpoint 和可视化 debug，再迁移更自然。

Q: 迁移时最怕丢什么？

A: 最怕丢 state contract、eval suite 和 HITL 语义。框架 API 可以重写，但用户审批边界、trace 证据、checkpoint 恢复必须保持。

Q: LangGraph 会不会让系统自动变 production-ready？

A: 不会。它提供 durable workflow primitives，但 auth、rate limit、data retention、eval、observability、deployment 和 cost control 仍然要你设计。

Q: 面试时怎么讲这一章？

A: 讲“我先用小 engine 学清楚 orchestrator 的 invariants，再保留 LangGraph 迁移适配层”。这比只说“我用了 LangGraph”更像 AI infra 工程师。

行业脉搏：把本章放到 2026 AI infra 里看

LangGraph 官方强调它不抽象 prompts 或 architecture，而是提供 long-running stateful workflow 的底层能力。

这正好说明 agent infra 的核心不是模板，而是状态、持久化、恢复和观察。
