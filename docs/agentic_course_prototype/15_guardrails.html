第 15 章：Guardrails：在 Agency 之前先做安全边界

Guardrails 不是让模型更听话，而是让系统先拒绝不该处理的输入和动作。

直接做实验 课程目录

这一章先解决什么问题

本项目在 public submission 进入 workflow 前做 secret 与 prompt-injection guardrail。

这体现一个重要原则：高风险输入不要等 agent 自己判断，应该在系统边界先筛掉。

Guardrail 还包括 body size、rate limit、run id validation、content type、security headers、public demo mode 限制。

开店不能等顾客走到收银台才检查是不是带了危险品。门口安检、货架权限、收银复核、监控录像都是不同层级的 guardrail。

扩展工程手册：把这一章做成可执行练习

这章真正解决的问题

第 15 章把系统边界放在模型能力之前：公开产品不能把任意文本直接交给 agent。攻击、误输入、secret 泄露、run id 猜测、超大请求和未授权审批都应该在 workflow 外层先被限制。

Request BoundaryFastAPI middleware 限制请求体大小、设置 security headers，并把异常变成可控响应。
Input Inspectioninspect_public_submission() 在创建 run 前扫描 secret 和 prompt injection pattern。
Run Identity_validate_run_id_or_404() 避免路径遍历和奇怪 run id 进入 checkpoint/store 层。
Approval Ownership公开模式下审批绑定 creator session，防止别人拿到 run_id 后替你批准。
Ops ExposureJOBAGENT_PUBLIC_DEMO_MODE 会隐藏敏感 ops surface，避免公开 demo 泄露过多运行细节。

代码解读：每个文件负责什么

jobagent/security/input_guardrails.py

输入安全扫描器。它返回结构化 GuardrailFinding，让 UI/API 能解释为什么拒绝，而不是只给一个模糊错误。

jobagent/web/app.py

安全边界最多的文件：body limit、headers、rate limit、run id validation、submission validation、public demo mode、approval owner session 都在这里。

tests/test_input_guardrails.py

验证 secret/prompt-injection pattern。这里适合加入未来真实攻击样例，作为安全 regression suite。

tests/test_web_app.py

覆盖 web public surface：创建 run、审批、ops route、run id validation、公开模式行为。安全补丁应该优先在这里加测试。

工程选择 Q&A

Q: Guardrail 应该 blocking 还是 warning？

A: secret、credential、越权外部写入、审批绕过应该 blocking；低质量输入、缺少 URL、信息不完整可以 warning 或引导用户补充。

Q: 模型级 guardrail 够吗？

A: 不够。模型 guardrail 是一层，但 web request、tool permission、MCP server、external side effect、HITL 都需要系统级边界。

Q: 误杀怎么办？

A: Finding 要可解释，UI 要给用户改写输入的机会。真正需要 override 的场景必须有审计记录和权限控制。

Q: 对 portfolio 来说安全做到什么程度？

A: 至少能讲清 threat model，并用测试证明 public route、approval、run id、request size、secret scanning 有基本保护。
